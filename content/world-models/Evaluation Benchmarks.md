### Some Interesting Papers

The two papers I found most interesting were **WBench: A Comprehensive Multi-turn Benchmark for Interactive Video World Model Evaluation** and **WorldBench: Disambiguating Physics for Diagnostic Evaluation of World Models** (see [[Video World Models]] for the complete benchmark catalogue).

### Problems These Papers Address

**WBench** is trying to solve the problem of evaluating interactive video world models in a unified way. The key issue is that current models do not all use the same inputs: some are controlled by text, some by camera poses, and some by discrete actions. That makes direct comparison difficult.

**WorldBench** is trying to solve a narrower but important problem: physics evaluations often mix several concepts together.

WorldBench tries to make physics evaluation more diagnostic by isolating one concept at a time. It also separates intuitive physical understanding from lower-level measurements such as friction coefficients or fluid viscosity, so the benchmark can say more precisely what kind of physical reasoning a model lacks.

### What They Have Not Solved Well

WBench still does not fully solve the problem of measuring real-world reliability. It uses many automatic metrics, including specialist vision models and large multimodal model judges. That is useful, but some scores are still indirect proxies for the behavior we actually care about. For example, a model can score reasonably on visual quality or judged interaction adherence while still being unreliable for planning, robotics, or long-horizon simulation.


## 1. Summary of Evaluation Objectives

### Group C: Control, Camera, and Action Fidelity

The common pattern: work out what camera path the generated video *actually* shows, then compare it to the path the model was *asked* to follow.

| Metric                                      | Long form                                                                                                              | What it measures and how                                                                                                                                                                                                                              | Used by                             |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| Translation error                           | Scale-invariant translation error from DROID-SLAM (where SLAM = **S**imultaneous **L**ocalization **a**nd **M**apping) | SLAM software re-traces the camera path implied by the video; the score is how far the camera's *position* drifts from the requested path (ignoring overall scale)                                                                                    | WorldMark, WorldScore, 4DWorldBench |
| Rotation error                              | Geodesic / angular rotation error                                                                                      | Same idea for camera *direction*: the angle between where the camera actually points and where it was told to point                                                                                                                                   | WorldMark, WorldScore, 4DWorldBench |
| Relative Pose Error (RPE)                   | Trajectory recovery via **ViPE** (**Vi**deo **P**ose **E**ngine)                                                       | Step-by-step (frame-to-frame) error between the executed and intended camera movement, for both position and rotation                                                                                                                                 | MIND                                |
| Action controllability                      | **IDM** (**I**nverse **D**ynamics **M**odel) accuracy                                                                  | A separate "action-guessing" model watches the generated video and infers which key or mouse action was taken; the score is how often its guess matches the commanded action (the guesser itself is reliable: 90.6% keyboard accuracy, R² 0.97 mouse) | GameWorld Score                     |
| Object success / content alignment          | Grounding-DINO (open-vocabulary object detector) + **CLIPScore** (CLIP text–image similarity)                          | An object detector checks that the requested object actually appears; CLIP checks the overall content matches the text                                                                                                                                | WorldScore                          |

### Group E: Physics and Causality

Three distinct measurement philosophies:

**E1. Direct, parameter-based ground truth** (WorldBench):

| Metric                                   | Long form                                    | What it measures and how                                                                                                                                                                                                                                                                            |
| ---------------------------------------- | -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Gravity / friction / viscosity estimates | -                                            | Track the object's motion across frames (with **SAM2** and known scene geometry), fit the trajectory to the expected physics equation, and read off the implied physical constant; then compare it to the real-world value. The pipeline is sanity-checked on real videos: it estimates gravity at 9.78–9.85 m/s² |
| Foreground mIoU                      | mean **I**ntersection **o**ver **U**nion | How well the generated object's position and shape overlap the ground-truth object, frame by frame                                                                                                                                                                                              |
| Background RMSE                      | **R**oot **M**ean **S**quared **E**rror  | Pixel difference in the static background; checks the scene doesn't change when it shouldn't                                                                                                                                                                                                   |

**E2. Learned-judge / rubric-based:**

| Approach | What it measures and how | Used by |
| --- | --- | --- |
| Five binary physics checks | An AI judge (a fine-tuned ~2B-parameter **VILA** vision-language model, trained on ~67K human labels) answers five pass/fail questions per video: does motion persist (Newtonian persistence), do solids behave like solids, do fluids behave like fluids, do objects avoid passing through each other, and does gravity hold | WorldModelBench |
| Causal fidelity + visual plausibility | Two WBench physics submetrics: *causal fidelity* checks whether event order and physical effects are coherent across categories including fluids/smoke, collisions, deformation, wind response, reflections/lighting, and human motion; *visual plausibility* is scored by a fine-tuned Qwen3-VL-30B-A3B judge trained on an internal ~6K human-rated video set, with reported PLCC 0.92 against its ground-truth labels | WBench |
| Three-stage PhyGenEval pipeline (0–3 scale) | Three steps: (1) find the key moment where the physical phenomenon should appear (via CLIP/**VQAScore**: **V**isual **Q**uestion **A**nswering score); (2) check events happen in the right order with before/during/after questions; (3) grade overall naturalness against a rubric written for that specific physical law. The three stage scores are averaged (rounded down), and multiple AI judges are ensembled for robustness | PhyGenBench |
| Adaptive question answering over captions | The generated video is first described in text (captioned); AI judges (**MLLM**s: **M**ultimodal **L**arge **L**anguage **M**odels) then answer ~10 auto-generated yes/no physics questions about that description, scored by answer accuracy | 4DWorldBench |

**E3. Human-grounded** (Physion-Eval):

| Metric                   | Long form                                               | What it measures and how                                                                                                                                                                                                                                                                                                            |
| ------------------------ | ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Youden's J               | J statistic (classically sensitivity + specificity − 1) | People watch a blinded 1:1 mix of real and generated videos and say which look physically realistic; the score is how much more often real videos pass than generated ones, higher means the fakes are easier to spot                                                                                                               |
| Expert diagnostic labels | -                                                       | Trained annotators mark each physical glitch: whether one exists, when it happens (to within 0.1 s), what type it is (8 categories: object permanence, temporal coherence, material/state, contact, causal sequence, force/motion, geometric/collision, other), how severe it is (1–5), their confidence, and a written explanation |

## 2. Evaluation / Benchmark Methodology

1. **Put different models into one shared test format.** World models do not accept the same controls: some take text, some take camera poses, some take keyboard/mouse actions, and some take camera matrices. Benchmarks such as WBench, WorldMark, iWorld-Bench, and WorldScore define one common task format first, then use preprocessing to translate that task into each model's native input format.

2. **Use learned judges for properties that are hard to specify directly.** Some qualities, such as physical plausibility, interaction success, and semantic consistency, cannot always be measured with a simple geometric or pixel-level reference. WorldModelBench trains a compact judge on ~67K human criterion labels; WBench combines specialist vision models, VLM scoring, and a visual-plausibility scorer trained on ~6K human-rated videos; PhyGenEval uses multiple VLM judges in a staged rubric. These learned scores are most defensible when they are checked against human preferences or expert labels.

## 3. Key Findings

1. **Visual quality is decoupled from world-model competence.** WBench finds navigation correlates near zero with video quality (−0.12) and consistency (−0.05); WorldMark finds quality and consistency largely uncorrelated; WorldModelBench's top model Kling scores 8.82/10 yet fully completes only 61% of tasks; VBench correlates with WorldModelBench physics at only ~0.28.

2. **Long-horizon degradation is universal.** WBench: navigation drops ~33 points by turn 4+; WorldBench: mIoU declines with prediction horizon; WorldScore: models struggle on long sequences; Matrix-Game's long-horizon evidence is only qualitative.

## 4. Conclusions

- **Direct ground truth beats semantic judging where available**: camera trajectories, reprojection error, masks, calibrated parameters, and simulator state are more defensible than VLM scores; learned judges should be reserved for properties that cannot be specified geometrically.
